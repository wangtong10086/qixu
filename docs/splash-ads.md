# 开屏广告适配

此功能通过栖序的应用进程钩子处理开屏入口，不依赖无障碍、VPN、域名黑名单或互联网控制服务。应用数据与安装包不修改。

## 使用

在“策略 → 开屏广告”查看适配状态，进入应用策略开启“屏蔽开屏广告”，保存后重新打开应用。首次增加 Vector 作用域需要结束目标旧进程并重开；普通开关和观察/执行模式通过本地快照同步到已连接进程。

```sh
fuxictl ads status
fuxictl ads enable com.zhihu.android --dry-run
fuxictl ads enable com.zhihu.android
fuxictl ads disable com.zhihu.android
fuxictl ads enable com.taobao.taobao
fuxictl ads retry com.taobao.taobao --dry-run
fuxictl ads retry com.taobao.taobao
```

`app.patch` / `app.replace` 的 `blockSplashAds` 字段与界面一致。功能只能逐应用启用，不能开启全局默认。配置方案分别保存开关。版本号不再作为拦截门槛：当前签名受信任且全部必需入口结构匹配时，更新后继续尝试。签名不同或入口缺失时放行应用，显示原因。

保存配置与 Vector 作用域同步是两个步骤。后者失败会报告错误；已保存的配置不会伪装成未保存。修复 Vector 后用 `fuxictl reconcile` 重新同步。启动根服务不依赖 Vector CLI 成功执行。

## 状态与边界

“已加载”表示适配入口注册完成；“已命中”表示应用侧上报至少一次入口拦截。仍须检查页面可用性。记录按秒合并，计数是诊断批次，不是广告曝光数。应用侧诊断不是可信安全事件，不驱动其他应用策略；自身启动健康判断还需核对系统退出记录。

独立 abstract UNIX socket `qixu.splash.v1` 仅允许已列入适配清单的包，由内核 peer UID 验证所有权。该通道只能获取自身广告配置或上报有限长度的诊断，不能访问完整配置、事件入口、CLI 或修改策略。管理 socket 的权限规则保持不变。应用确认对端 UID 为 root。

钩子使用内存开关。根服务断开后停止广告拦截；已安装钩子的进程在下一次 Activity 恢复时重连。若首次启动时服务不可用，没有安装广告钩子，需要重新启动该应用。此时不阻止应用启动。

不处理信息流、激励广告或付费权益，不模拟广告点击、曝光或奖励回调。分析提取的第三方 APK 和反编译输出仅保存在忽略提交的 private 目录。

## 实机验收

- 对照未启用、启用和再次关闭；保存当前应用版本与真实入口命中。
- 冷启动、回前台、缓存广告、断网、服务重启；检查主页可达及无新增崩溃。
- QQ 音乐播放、高德导航需单独验证；无广告命中不等于这些业务已通过。
- 自动测试遇到其他前台应用即停止，不点击登录、支付或权限同意。
- 不自动改变银行、钱包、输入法的作用域和策略。

## 跨版本异常恢复

本地服务把健康记录保存在 `splash-health.json`，与配置方案分开。键包含包名、版本、安装更新时间和适配器修订。进程身份取自本地 socket 的凭据，不接受应用自报 PID。

只有已加载且开启拦截的主进程参与统计。每次新进程连接前读取系统退出记录：启动 60 秒内的 Java/原生崩溃或 ANR 退出计为异常，5 分钟内连续两次则暂停当前安装版本；首次异常仍可能发生。手动强停、系统回收、其他子进程和旧启动记录不计。关闭策略会解除当前会话的异常归因；主线程持续可响应 60 秒后清除失败计数。

暂停不改变 `blockSplashAds`，也不影响其他应用。记录跨服务重启保留；应用更新或适配器修订后重新检查。界面“重新尝试”或 `ads retry PACKAGE` 清除该应用的暂停记录，随后重新打开应用。重试不会自动重启应用、改变模式或打开原本关闭的开关。

`ads status` 的 `matched` 表示签名匹配，不代表入口已加载或广告已命中。`inspectedVersion` 为参考版本，`crossVersion` 表示与参考版本不同；`suspended` / `suspendReason` 为异常暂停状态。`report.state` 区分入口加载、命中和不匹配；健康心跳不会覆盖最近拦截结果。原协议字段与开关保持兼容。

健康检查只在连接、进程退出记录核对、策略变更及一次性主线程延迟回调时工作，没有常驻轮询或联网依赖。退出记录不足以证明崩溃由栖序导致，因此暂停原因使用“疑似兼容异常”。
