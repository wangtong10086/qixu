# 实机验证记录

设备：Xiaomi 13，Android 16，内核 5.15，Magisk 30.7，Vector 2.2 / API 102。
记录日期：2026-10-18。记录不包含设备标识、用户配置、消息内容或认证资料。

## 已验证

- 固定项目签名的 release APK；签名管理界面与独立 root 服务连接。
- API 102 模块实际加载到 system_server，主用户作用域为 system/0。
- 自启动、广播、服务、作业、WakeLock、前台、活动任务、缓存冻结、包及权限变化、通知钩子就绪。
- CLI 预览和失败输入不写配置；完整替换应用例外会删除旧字段；过期版本不能覆盖新编辑。
- 0.1 界面、连续两次保存和恢复继承；重装验证应用后继承当前默认模板。0.2 UI 的独立验收见 [qixu/README.md](qixu/README.md)。
- 临时应用冷启动广播拦截，用户活动可启动；退到后台后内核 nice 与 uclamp 生效。
- 独立及隔离进程的 CPU 设置；memory.high 实值；常驻 Binder 接口。仅设置 uclamp、cpuNice=0 时保留原优先级。
- 恢复内存/调度原值，并保留其他组件在期间修改的调度字段。
- 危险权限撤销、UID AppOps 拒绝及原值恢复。
- 智能待机可进入 rare 桶并恢复原桶；充电时实际 idle 受 Android 系统豁免。
- 合成可信推送：代理通知、后台进程启动、进入前台后清除通知。
- 通知渠道明确使用管理应用 UID，避免 system_server 调用者 UID 错配。
- 普通未授权应用的 socket 请求被拒绝。
- 执行状态下重启 root 服务，等待系统前台快照后恢复执行。
- 离线恢复撤回 CPU、内存、权限、网络限制，只关闭自己的 Vector 模块，Thanox 保持不变。
- 限定验证应用的测试结束均恢复原策略；临时验证 APK 已卸载，充电亮屏设置已恢复。

## 网络

内核 BPF 验证器与实际附加通过。保留原 Android 网络程序，先填尾调用表再替换入口，
恢复时核对仍为自己的入口。0.6 为资源统计保留计数程序；无规则时不施加预算，显式恢复或升级时撤下入口。
上传限速使用拥塞丢包返回值，避免向 UDP 应用误报网络权限错误。

| 测试 | 配置 | 实测 |
| --- | --- | --- |
| IPv4 TCP 上传 | 512,000 bit/s | 1,163,264 bytes / 20,726 ms，449,006 bit/s |
| IPv4 TCP 下载 | 2,000,000 bit/s | 7,356,416 bytes / 29,558 ms，1,991,045 bit/s |
| IPv4 UDP 上传 | 512,000 bit/s | 通过线速字节 1,344,694，丢弃 15,468 包；发送应用正常继续发送 |
| IPv6 UDP 下载 | 2,000,000 bit/s | 4,869,600 bytes / 20,997 ms，1,855,350 bit/s；丢弃 11,732 包 |

以上使用本机 loopback，包含配置的 64 KiB 初始突发额度。TCP 实际吞吐可低于上限。
计数在所有规则关闭、程序卸载或重启后重新开始。

## 0.6.0-alpha1 资源统计与进程限制（2026-10-21）

- 主机测试：core 48、app debug 12 项通过；release 构建和 lint 通过（既有警告保留）。native token bucket 边界测试通过。
- 实机 eBPF 验证器加载通过，socket cgroup ID 与 arm64 kernfs inode 对应确认。
- 临时 worker 前台 nice 9／uclamp 512，后台 nice 14／uclamp 256；内存 high 96 MiB、max 192 MiB 实际文件值匹配，恢复继承后 high 回到 max；PSS 可读。
- 独立 network 进程 TCP 上传 467,928 bit/s（上限 512,000），下载 1,012,719 bit/s（上限 1,000,000，包含 64 KiB 初始突发）。应用总预算同时保留。IPv4 上传／IPv6 下载 UDP 回归通过，超额计数可读。
- 上述网络测试均为本机 loopback；不能据此声称完成真实 VPN 或业务网络兼容验收。
- 独立临时数据库通过分钟加权平均、15 分钟聚合、七天过期、清空和关闭后重开测试。完整七天自然运行尚未验证。
- 整机、应用、进程资源页、实时／七天切换和进程限制表单已经实机查看。编辑后返回会提示放弃未保存内容；放弃后返回进程列表，从应用策略返回也正确回到资源页。全部原策略内容（忽略修订号）与测试前一致，临时 probe 无残留覆盖。截图仅留在 private，包含本机应用信息，不纳入公开仓库。

当前内核没有 CPU 时间硬配额，继续使用 nice／uclamp 和 cgroup 内存预算；没有刷入内核。新进程规则可能等待最多五秒校准，首次绑定前仍受应用 UID 规则约束。

最后一次调度优化后再次验证 worker 前台／后台 CPU 参数、PSS、内存限制恢复均通过；测试 APK 已卸载。当前服务 17 项系统钩子就绪、执行模式保持，配置内容比较通过。

采样开销：最终版本后台 30.10 秒窗口，整个 root 管理服务消耗约 8.9% 单核 CPU（非新增采样模块的独立开销）；此为短时工作台测量，不代表长期耗电或息屏待机。
