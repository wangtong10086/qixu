# Thanox 迁移约定

迁移先生成带时间戳的私有备份，校验每份配置的 SHA-256，并检查完整归档的 gzip CRC 和 tar 结构。
私有文件不进入源码仓库。导入只写观察模式，启用执行与停用 Thanox 是后续独立步骤。

本机配置按实际总开关解释，不能仅凭名单非空就启用功能。

| 旧设置 | 新策略 |
| --- | --- |
| 自启动/后台名单 | 原名单存档；按用户选择，普通应用即时继承新默认模板 |
| VPN 常驻 | 保留逐应用 resident 例外与关键服务保护 |
| 智能待机 V2 | 保留 restricted 例外；用户前台、音乐、导航和下载期间豁免 |
| WakeLock 名单 | 保留完整 tag 的逐应用拒绝规则 |
| 划掉任务清理名单 | 本机总开关关闭，仅存档，不因导入重新启用 |
| 权限/AppOps | 本机存储项均为 allow，初始隐私模板保持空 |
| 权限提醒 | 未配置提醒操作集合，无活动行为需要迁移 |
| 微信推送代理 | 保留开启、显示内容、推送后后台启动、声音/振动等选项 |
| 3 条自动化 | 转换为类型化的推送记录、推送后缓存回收、离开前台后缓存回收 |

自动化转换核对旧规则的条件、动作、延迟与优先级摘要。未知或被修改的脚本会拒绝导入，
不会执行来自备份的 MVEL 或任意 shell。微信缓存回收使用 `am kill`，避开前台、活动任务和音频焦点，
新事件会替换之前的延迟回收，重新进入前台会取消待执行回收。

关键的系统、输入法、钱包、银行、消息和 VPN 服务保持宽松基线。具体例外可用 `explain` 审查。
默认拒绝普通应用自启动是这次新模板的有意变化；迁移不把每个旧应用固化成一份默认配置副本。

```sh
python3 tools/export_thanos.py
python3 tools/stage_migration.py private/baseline-YYYYMMDD-HHMMSS
```

第二步先预览。已暂存的同一备份可用 CLI 的 `migration import DIRECTORY --dry-run` 再次预览，
去掉 `--dry-run` 后导入到观察模式。备份目录同时校验配置与归档，不覆盖既有目录。

只有完成系统钩子、CLI/界面写入、推送代理、资源限制和恢复演练后，才启用实际模板并停用 Thanox。
停用保留 Thanox APK 与数据，便于恢复。最终仍需检查实际应用和重启后的状态，
不能把 Play Integrity 检测通过等同于 Wallet 可支付，也不能把合成推送当成真实微信 FCM 端到端验证。

## 本机接管记录

已导入 3 个逐应用例外、3 条自动化和微信推送代理；普通应用即时继承新模板。
Thanox 的 Vector 模块与应用已停用，未卸载、未清除数据。
旧兼容模块的回调继续处理开机和安装包变化，只停用重复的微信回收分支。
原回调保存在 root 私有目录；`restore-thanox.sh` 恢复原回调、撤回新限制并重新启用 Thanox。
