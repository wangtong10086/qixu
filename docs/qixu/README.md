# 栖序 · Qixu 0.4.1

采用 A「原生简洁」方案的正式 Compose 管理界面。包名仍为 `dev.local.fuxicontrol`，沿用原签名、服务协议、CLI 和配置。应用名称及图标更新，不迁移或清空策略数据。

## 页面

- **概览**：真实服务连接、执行模式、系统钩子就绪数量、应用与例外数量；前台／可见／后台／缓存进程统计可点击筛选。没有估算省电百分比。
- **应用**：名称／包名／权限／策略内容搜索，区分声明与已授予权限；支持运行状态及继承／例外／关键服务筛选。列表和详情显示真实应用图标。
- **应用策略／默认模板**：启动与后台、CPU 与内存、网络、权限与唤醒锁表单。逐项恢复继承及整个应用恢复继承；速率单位 bit/s，内存 MiB，突发窗口 Bytes；0 速率表示关闭限速。
- **策略**：搜索入口和匹配应用、默认模板、自动化与推送。自动化通过应用选择、事件、动作、延迟与启用开关编辑；推送通过逐应用开关配置。
- **设置**：系统能力状态列表、事件时间线、受控流量与丢包计数、CLI 帮助、配置管理和开源许可。

## 交互约束

所有写入继续带 `expectedRevision`；冲突必须重新加载，不覆盖其他客户端的新配置。服务断开禁用写入，可重新连接；业务校验错误不误报为连接中断。未保存返回会提醒。模板保存前显示更改字段与有效策略实际变化的已安装应用数；关键角色与逐项例外参与计算。服务预检仍为最终可执行性判定，界面表单不新增内核能力。

数值在 UI 边界验证并转换为整数 JSON；多行唤醒锁标签转换为数组。权限和 AppOps 以条目形式编辑，没有内置拒绝清单。

## 品牌与图标

中文名 **栖序**，英文标识 **Qixu**。启动图标以纯色 `#6750A4` 和白色调节轨道表示可配置的后台秩序。包含 Android adaptive icon 与 monochrome 层，原始矢量稿见 [icon.svg](icon.svg)。界面图标来自 Lucide，ISC 许可随 APK 分发。

使用原生 Material 3 组件提供触摸反馈和水波纹，浅色主题、紫色强调色、圆角状态容器、列表分隔线。默认左对齐，保留滚动与系统安全区。

## 更新与回退

0.2 只覆盖安装管理 APK。0.3 新增服务查询接口，需要使用安装脚本同时更新原签名 APK 和 root 服务；先备份已有控制器目录，重启服务后核对模式、钩子和策略。本次不修改系统钩子实现。覆盖安装前的 APK 与完整配置存放在本机 `private/qixu-before-*`（不入库）。备份 APK 保留供回退。Android 可能拒绝直接降级安装；如需回退，应使用不低于当前版本号的原签名回退构建，不要卸载应用或清数据。

Vector 可能因模块 APK 更新提示重启。本次未改变钩子逻辑，当前运行状态已检查；重启后的完整银行与 Wallet 回归不属于此次 UI 验收。

### 0.3 搜索与运行视图

搜索支持名称、包名、声明权限、已授予权限和有效策略关键词；中文权限别名与原始权限名都可输入。多个词按 AND 匹配。
应用行显示匹配权限的授予状态；“已授予”不等于所有 AppOps 和前后台使用条件均已满足。
概览数字可点击进入相应运行分组，应用页还支持合并的“运行中”筛选；缓存单独展示。
运行分组按系统进程 importance，不把配置数量、共享 UID 或缓存进程误作活动窗口/CPU 活跃证明。
可见时每 5 秒刷新；暂停或离开相关页面停止发起轮询。0.3.1 隐去常驻的时间、刷新机制、设计版本和实现背景说明，保留状态、输入帮助和异常提示。

应用列表、运行筛选、策略搜索结果和应用详情标题显示 PackageManager 提供的真实应用图标。
仅加载可见项；128px 图标、64 项 LRU 缓存、最多 3 个并发请求。应用更新后按 lastUpdateTime 失效。
图标加载失败时保留标有“暂不可用”的占位图标，文字和配置操作仍可用。


0.3 已完成验证：20 项 core 测试、3 项表单测试、Release 构建与 lint；实机声明/已授予相机权限集合与页面计数一致，管理应用 PID 与进程快照一致，名称搜索、策略搜索、应用列表/详情/搜索结果图标均通过。只读验收前后配置完全一致。

运行生命周期实测：临时安装独立预览应用，冷启动后进入运行快照，强制停止后不再出现；随后卸载预览应用。原有应用详情、默认模板、保存摘要、放弃编辑、诊断、自动化及推送页面完成回归。包事件会独立推进配置版本，验收脚本按全部策略内容比较、仅排除 revision；升级及测试结束后的策略内容与最初基线一致。


### 0.4 设置与返回

设置不再显示原始 JSON。网络统计按上传/下载展示通过及丢弃的字节和包数，并显示对应应用图标；共享 UID 的计数不重复计算为每个应用的独立流量。未加载或没有流量时显示相应空状态。
配置管理提供运行模式、默认模板、应用例外、自动化及推送入口。JSON 导出/导入仍由 CLI 提供。
自动化支持修改应用、规则名、事件、动作、毫秒延迟与启用状态；推送提供全部六个布尔字段。新项目默认关闭，增删改先留在草稿，确认保存后才应用。
返回路径按入口保存：设置子页返回设置，配置管理中的表单返回配置管理，应用例外详情返回例外列表；左右边缘手势和顶栏返回一致。未保存返回先确认放弃，重载冲突不会重复压入页面。

## 配置方案与资源限制

概览的“切换配置方案”和设置 → 配置管理 → 配置方案可复制当前配置并使用，或切换已有方案。
修改自动保存到当前方案，切换前确认影响范围。方案包含运行模式、默认模板、应用例外、自动化和推送。
配置与所有方案共同保存在服务端的原子配置文档中；内部仍使用版本校验，不在界面显示版本号。

上传和下载限速可分别开启，提供 256 kbit/s、1/5/10 Mbit/s 预设及整数 bit/s 自定义值。
超速流量被丢弃，允许设置的突发窗口；共享 UID 共用额度。统计页可查看通过量、丢弃量和丢包数。
入站限速发生在数据到达设备后，不保证减少运营商计费流量，也不等同于省电效果。

CPU 时间硬配额当前不可用，原因和内核改动研究见 [CPU 配额调查](../cpu-quota.md)。
