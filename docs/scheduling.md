# 高级 CPU 核心调度

栖序 0.7 使用现有 root 服务通过 JNI 调用 Linux `sched_getaffinity` / `sched_setaffinity`。它控制线程**允许在哪些核心上运行**；时间配额控制**可以运行多久**，两者独立且同时有效。管理通信沿用 Binder，不新增模块、网络监听或实时调度器。

## 核心范围

通过 sysfs 的 CPU 容量自动分组，小米 13 当前内核为：小核 0–2，大核 3–6，超大核 7。查询 `fuxictl cpu topology` 查看实际编号、在线情况、容量和最高频率；不把这组编号用于其他设备。缺少容量数据时不猜测分组，不支持的分组会被拒绝。

选择值：

| 值 | 含义 |
| --- | --- |
| `system` | 不增加该层的自定义核心限制 |
| `little` | 最低容量组 |
| `big` | 小核与最高容量组之间的核心组 |
| `prime` | 最高容量组；同构设备不单独推断超大核 |
| `0-2,4` | 显式 CPU 列表，可以混用范围与单个编号 |

两个容量组的设备只有 little 和 prime，big 不可用。当前后端针对已验收的 Android 16、cpuset v1 路径；不声称通用于任意 ROM。

运行范围取以下交集：请求核心 ∩ 在线核心 ∩ 当前 Android cpuset ∩ 启用的后台小核上限。不会移动到更宽的 cpuset，也不改频率或热管理。后台只指定大核、且启用小核上限的配置在预检时拒绝。运行中系统范围或在线状态改变导致无交集时，显示 blocked；独立后台上限仍执行，不能借此放开大核。没有可用目标时不设置空掩码、不冻结应用。

## 后台上限与前台

方案级字段：

```json
"scheduling": {"backgroundSmallCoresOnly": true}
```

开启后，后台应用及可确认归属的隔离进程只用小核，包括音乐、导航、下载、受保护应用。不会顺便取消它们现有的 CPU 时间配额、内存或清理豁免。前台默认不增加限制，但可以明确配置前台进程、线程选核。

前后台使用现有 UID 生命周期事件，并通过系统 UID 状态复核 TOP／PERSISTENT_UI，不把“存在前台服务通知”视为用户前台页面。PERSISTENT 常驻状态不等于前台界面。共享 UID 共同处于该阶段。系统自身的 cpuset 仍然优先，因此前台手动选核也可能只部分可用。

全新及迁移配置的后台上限默认关闭，避免升级立刻改变整机调度；用户在默认核心调度页或 CLI 启用。设备验收后按用户选择开启当前方案。其他命名方案保留迁移后的原行为，切换前检查各自设置。

## 继承与线程匹配

默认模板、应用 `cpuAffinity` 均按阶段继承：

```json
"cpuAffinity": {"foreground":"system", "background":"little"}
```

进程规则继续以完整进程名为键，在 `foreground`、`background` 下增加字符串字段 `cpuAffinity`。省略就继承应用。线程规则放在对应进程的 `threads` 有序数组中，格式见 [线程示例](../examples/thread-affinity.json)。

- `id`：1–64 个字母、数字、下划线或连字符，同一进程内唯一。
- `match.type`：`main` 匹配主线程，不带 name；`exact` 和 `glob` 需要 name。
- 通配符仅 `*` 和 `?`，不是正则表达式。按 `/proc/PID/task/TID/comm` 匹配，可能截断到 15 字节，不是完整 Java 线程名。
- 每个阶段取第一条匹配且提供该阶段配置的规则，没匹配则继承进程。重复线程名全部匹配。
- 线程规则本版只配置核心，不新增线程独立 CFS 时间配额、内存限制或实时优先级。
- 用名字持久配置，不使用 PID/TID 作规则键；应用改名、更新改变线程名后需要重新核对。

下层覆盖上层选核，不代表能突破系统和全局后台边界。共享 UID 的应用级配置会传播到同 UID 成员，冲突被拒绝；逐进程规则在共享 UID 内合并，同名进程冲突也会拒绝。

## 生效、查看与恢复

前后台和进程事件触发校准；新线程、改名和系统重分组另由现有五秒周期校准，不新增全局高频轮询。它不是对第一条指令的同步拦截，也不承诺每个瞬间都不越界。

- `cpu status PACKAGE` 返回阶段、规则来源、请求／有效／实际核心和上次校准时间。
- `thread list PACKAGE PROCESS` 读取当前线程、允许核心、最近运行核心和区间 CPU。首次 CPU 样本为空，百分比按整机总 CPU 计。
- 允许核心表示可运行范围；最近核心仅是 `/proc` 的一次采样，不表示长期驻留该核心。
- `applied` / `restricted` / `blocked` / `error` / `system` / `exited` 区分执行结果；`verified` 是当次内核读回，不能当作以后永远有效。
- 进程没启动时保留规则等待匹配；观察模式仅查看，不执行绑定。

恢复日志保存在私有服务目录的 `affinity.json`，按 boot ID、PID／线程启动时间核对身份，避免 PID 重用。只恢复仍与自身最后应用值相符的状态，不覆盖系统后来修改的值。新线程继承栖序掩码时也记录恢复基线；恢复时交集当前系统可用核心。

停止执行可用 `mode observe`；紧急恢复脚本同样撤销自身亲和性。回退旧版本前先用新版本恢复，随后恢复旧 APK、原生库和 schema 备份。不要让旧程序读取 schema 4 或新的恢复日志。

## 验收范围

自动测试使用临时 probe，不改银行或聊天应用的配置。检查精确名／通配符、主线程、线程重建、阶段切换、后台活动任务、配置冲突、恢复和既有 CPU 配额。最终结果见 [验收记录](validation.md)。功能测试不等于已经证明省电效果；绑定小核也可能延长工作完成时间。

参考：[Linux 亲和性接口](https://man7.org/linux/man-pages/man2/sched_setaffinity.2.html)、[Android task profiles](https://source.android.com/docs/core/perf/cgroups)。
